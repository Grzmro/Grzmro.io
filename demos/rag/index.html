Retrieval you can watch happen

The interesting part of a RAG system is not that a model answers — it is which passages it was allowed to answer from, and whether anything it said can be traced back to them. So this page runs the retrieval stage in front of you and shows every number it produced.

Retrieval runs live Dense search, BM25 and rank fusion, ported from the project and running in this tab over the same vectors Chroma holds.
Verified against the service All 35 questions in both modes, 350 ranked passages, reproduced exactly — the check is a script in the repo, not a claim.
Answers are recordings Generation needs an API key, which cannot live in a static page. Claude's answers come from real evaluation runs, judge scores included.

Retrieval mode

Free text needs the query encoder itself — the same bge-small-en-v1.5 checkpoint the pipeline uses, 8-bit quantised, running on ONNX in this tab. Nothing is sent anywhere.

The failure this is built to prevent

        

          A retrieval system that always answers is easy. The hard requirement is that it
          declines when the corpus does not hold the answer — including when the
          corpus talks about the topic at length and simply never states the fact being asked for.
          That is where a language model's general knowledge quietly fills the gap and the answer
          stops being traceable to anything.
        

        

          Nine of the questions in the picker are unanswerable by construction. The pipeline is
          expected to return INSUFFICIENT_CONTEXT and an empty citation list rather
          than a plausible sentence. Twenty more are a discrimination set: same corpus, but each
          one is built so a dense-only channel can plausibly rank the right passage below the cut.
        

        

          Try “Who must approve access to Restricted data…” and switch between the
          two retrieval modes. Dense search alone misses the passage and the model refuses to
          answer; adding the lexical channel surfaces it and the same model answers correctly. The
          generation step never changed — only what it was allowed to read.
        

      


      
      

        

          
What the evaluation runs measured

          

            Every answer above was scored by a second model that decomposes it into atomic claims
            and marks each one against the retrieved passages only, alongside deterministic checks
            that need no model at all — retrieval recall, dangling citation markers, required
            content, and whether abstention happened where it should.
          

        

        

          

            
              Cross-encoder reranking is measured here but not offered above: it needs a model
              rather than a formula, so the browser cannot reproduce its ordering, and showing
              passages in an order the recorded answer's citation markers do not match would be
              worse than leaving it out.
            
          

        

      


      
      

        
What this demo does not tell you

        
    
          
  • 
            The corpus is 3 documents, 11 chunks — a deliberately small fixture
            for testing behaviour, not a demonstration of scale. With top_k = 5,
            every query retrieves nearly half of it, which is why the regression set scores 100%
            on every configuration and the discrimination set exists at all.
          
    • 
          
  • 
            Answers are recorded, not generated now. They came from real runs of
            the pipeline against the Anthropic API, but the wording you see is fixed. A question
            you type yourself gets retrieval and a context block — never an invented answer.
          
    • 
          
  • 
            The browser embeds free text with an 8-bit quantised copy of the
            encoder. On the 35 curated questions it picks the same top passage every time and the
            same top-5 set every time, with two of them ordered differently inside that set; the
            unquantised model reproduces the service exactly.
          
    • 
          
  • 
            Groundedness is scored by a language model, so it is
            evidence, not proof. The checks that do not need a model — dangling
            markers, retrieval recall, required content, abstention accuracy — are the ones that
            cannot flatter the system.
          
    • 
        

        

          The exporter, the ported retrieval stack and the script that checks the port against the
          Python service are all in the portfolio repository; the pipeline itself is in the project
          repository.
